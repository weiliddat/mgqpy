# mgqpy compared with other offline MongoDB filter matchers

Generated by [`report.py`](../report.py) from the JSON in this directory. Method, library selection and rerun instructions: [README.md](../README.md). JavaScript libraries are in the [appendix](#appendix-javascript-sift-and-mingo).

## Libraries

| Library | Version | Entry point | Notes |
| --- | --- | --- | --- |
| mgqpy | 1.0.2 (working tree) | `mgqpy.Query(q).test(d)` | Second to tinymongo on the new queries and the MongoDB manual examples; highest on the full corpus, which it was developed against. No `$type`, `$comment`, `$expr`, `$jsonSchema` or bitwise operators. Regex uses Python `re`, so `\w` matches Unicode letters and PCRE-only syntax such as `(?-i)` is rejected. Fastest Python matcher on most timed cases, but construction compiles the whole query, so single use is slower than libraries that interpret the filter directly. |
| mongomock | 4.3.0 | `mongomock.filtering.filter_applies(q, d) (used by Collection.find)` | No `$mod`; `$type` codes are rejected but aliases work. Embedded-document equality ignores key order (MongoDB compares it). Much faster than mgqpy for embedded-document equality and faster for single use on about half the cases; no separate construction step. |
| mongoquery | 1.4.3 | `mongoquery.Query(q).match(d)` | Targets MongoDB 3.4 semantics. Raises `TypeError` on many mixed-type comparisons and accepts most invalid queries. Construction only stores the query, so it is the fastest to construct and often faster for single use. |
| mongo-query-match | 2.0.0 | `mongo-query-match: mongoquery.Query(q).match(d) (fork of mongoquery)` | Fork of mongoquery with the same behaviour on this corpus (one query differs). |
| montydb | 2.5.6 | `montydb.engine.queries.QueryFilter(q)(d), bson on, mongo_version=4.2` | Supports `$type` and `$mod`; differs from MongoDB on NaN, `$exists` with non-boolean values and empty path components. Slowest Python matcher here. |
| tinymongo | 1.3.1 | `tinymongo.table_backends: validate_filter_operators(q); matches_filter(d, q)` | Most compatible on the new queries and the MongoDB manual examples, including `$type`; rejects nearly every query MongoDB rejects and raised on one valid query (PCRE `(?-i)`). Slower than mgqpy at matching on almost every case. |
| mongita | 1.2.0 | `mongita.collection: _validate_filter(q); _doc_matches_slow_filters(d, q) (unindexed find)` | Supports only `$eq`, `$ne`, `$in`, `$nin`, `$gt`, `$gte`, `$lt`, `$lte` and implicit equality on fields; `$and`/`$or`/`$nor` are treated as field names. Fast where it is correct, because it does little work. |

## Compatibility with MongoDB

Ground truth: `find` on MongoDB 7.0.45, 8.0.15; the servers agree on every query (rejection messages differ between versions, codes do not). A query agrees only if the library returns exactly the server's set of matching documents; one wrong document or one exception counts as a disagreement. Three query sets:

- **New queries**: 746 queries written for this comparison and not used to develop any library. Headline.
- **MongoDB manual examples**: the filters and sample documents from the MongoDB manual's query tutorials and operator pages ([`corpus_docs.py`](../corpus_docs.py) links each page). Independent of everyone here.
- **Full corpus**: adds 4974 queries from the real-server differential that mgqpy 1.0.2 was developed against, so mgqpy's result on it is expected, not independent. 506 documents in all. Also 36 queries MongoDB rejects, for error behaviour.
